## 1 引言

### 1.1 文档目的
本文档用于明确“口算练习软件系统”的需求边界、功能规格和非功能需求，为后续概要设计、详细设计、编码与测试提供统一依据。

### 1.2 项目背景
本项目面向小学生口算训练场景，开发一个可在命令行运行的题目生成系统。系统核心能力是按约束自动生成加减法口算题并输出参考答案。  
当前项目已完成 `project001` 到 `project005` 五轮初步迭代，功能逐步从“固定题量输出”演进为“可配置题型、题量、范围、去重及可行性提示”。

### 1.3 术语定义
- 题型：加法、减法、混合（加减随机）。
- 题目数量：用户请求生成的习题条数。
- 运算结果范围：口算结果上界，范围为 `0 ~ maxValue`。
- 不重复题目：同一批次内，算式字符串不重复。
- 约束类（Constraint）：封装范围、合法性校验和可生成题量估算的业务对象。

## 2 业务流程描述

### 2.1 业务目标流程
1. 用户启动程序。  
2. 系统展示菜单（加法/减法/混合）。  
3. 用户输入题型、题量、结果范围（`project005`）。  
4. 系统根据约束随机生成题目并去重。  
5. 系统输出练习题。  
6. 系统输出参考答案。  
7. 系统输出统计信息（如生成成功数、尝试次数、混合题型分布、范围警告）。

### 2.2 异常/边界流程
1. 当题量过大且在给定范围内无法生成足够不重复题目时，系统给出警告并输出当前已生成题目。  
2. 当生成尝试次数超过上限（`count * 10`）时，系统停止生成，避免死循环。  
3. 输入参数非法（如负数、非数字）在当前版本中缺少完整校验，后续迭代需补齐。

## 3 任务概述

### 3.1 目标
- 支持不同题型的口算题自动生成。  
- 支持题量可配置。  
- 支持结果范围可配置。  
- 保证同批次题目不重复。  
- 输出可直接用于练习与核对的题目和答案。

### 3.2 运行环境

#### 3.2.1 软件运行环境
- 操作系统：Windows（当前开发环境）。
- 开发语言：Java。
- 运行方式：命令行（Console）。

### 3.3 功能划分
- F1：菜单与参数输入模块。
- F2：题目生成模块（随机数 + 约束控制）。
- F3：题目去重模块（HashSet）。
- F4：练习题输出模块。
- F5：答案输出模块。
- F6：约束与统计提示模块（Constraint + 生成信息反馈）。

### 3.4 功能描述

#### 3.4.1 F1 菜单与参数输入
- 系统应展示可选题型：`1-加法`、`2-减法`、`3-混合`。
- 系统应接收题目数量输入。
- 系统应接收结果范围上界输入（`project005`）。

#### 3.4.2 F2 题目生成
- 加法生成规则：`a + b`，满足 `a + b <= maxValue`。
- 减法生成规则：`a - b`，满足 `a >= b` 且 `a <= maxValue`。
- 混合规则：在加法与减法之间随机选择。
- 输出数据：题目文本数组 + 答案数组。

#### 3.4.3 F3 题目去重
- 系统应在单次生成中对算式字符串做去重。
- 去重结构采用 `HashSet<String>`。
- 当无法满足请求题量时，系统应输出可读警告信息。

#### 3.4.4 F4/F5 题目与答案输出
- 系统应按序号输出练习题，格式统一。
- 系统应按序号输出对应答案。
- 每10题可换行分组，提升可读性（`project005`）。

#### 3.4.5 F6 约束与统计提示
- 系统应显示当前数值范围描述（如“0-20（20以内）”）。
- 系统应估算范围内可生成的不重复题目上限。
- 混合模式下，系统应输出加减题数量分布。
- 系统应输出总尝试次数。

### 3.5 迭代映射（代码到需求）
- `project001`：固定50题，100以内加减法，输出题目和答案。  
- `project002`：新增菜单、题型选择、题量可配置、模块化方法。  
- `project003`：新增混合题型。  
- `project004`：新增去重机制。  
- `project005`：新增范围约束、约束类封装、生成上限提示、尝试次数保护、混合题分布统计。

## 4 性能描述

### 4.1 响应性能
- 在普通教学机环境下，生成100道题应在1秒内完成（参考目标值）。
- 当范围过小且题量过大时，系统应在有限尝试次数内返回结果，不长时间阻塞。

### 4.2 可靠性
- 系统应保证输出答案与题目一一对应。
- 系统应保证输出算式满足基础数学约束（不出现负结果减法、超范围加法结果）。

### 4.3 可维护性
- 约束逻辑集中于 `Constraint` 类，便于扩展乘除法、分数等后续需求。
- 生成、打印、菜单等模块职责相对清晰，便于单元测试补充。

### 4.4 适应性
- 通过参数化输入适应不同年级难度。  
- 可扩展为图形界面或Web版本，核心生成逻辑可复用。

## 5 运行需求

### 5.1 用户界面需求
- 当前版本采用控制台文本界面。
- 提示语应简洁明确，输入顺序固定，降低误操作概率。
- 输出格式应对齐，便于打印或截图使用。

### 5.2 软件接口需求
- 当前版本无外部网络接口与数据库接口。
- 预留扩展方向：
  - 文件导出接口（TXT/CSV/PDF）。
  - 学生成绩记录接口。
  - 教学平台对接接口（后续版本）。

### 5.3 数据需求
- 输入数据：题型、题量、结果范围。
- 处理中间数据：题目集合、答案集合、去重集合、统计计数。
- 输出数据：练习题文本、答案文本、统计提示信息。

### 5.4 约束与风险
- 当前版本输入校验不足（如非数字输入），存在异常退出风险。
- 题目去重基于字符串，未做算式等价归一化（例如 `2+3` 与 `3+2` 视为不同）。
- 当题量极大时，尝试次数上限可能导致“未生成满额”情况，属于可接受退化行为。

## 6 验收标准（建议补充）
1. 能根据用户选择正确生成加法/减法/混合题。  
2. 生成题目数量与请求一致；若不一致需给出明确警告。  
3. 同批次无重复算式。  
4. 所有答案计算正确且与题目逐条对应。  
5. 结果范围约束生效。  
6. 混合模式可输出题型分布与尝试次数信息。

## 7 后续迭代建议
1. 增加输入合法性校验与异常恢复。  
2. 增加文件导出（题目卷/答案卷分离）。  
3. 增加单元测试与自动化验收脚本。  
4. 增加题目难度等级、乘除法和括号表达式支持。
